现在需要新增一个特性功能，在画布上框选多个节点后，可以实现批量生成的任务，请你作为anthropic顶级的产品经理和架构师，请帮我设计这块功能。

这块能力现在是断的。画布已经能框选、多选工具栏也有「打组 / 副本 / 导出」，但没有对已选节点批量出图/出视频。现有「生成」都是别的入口：

单节点：Dock 点生成 → generateForNode
构图实例：点组内任一节点，会按边拓扑顺序把整组跑完
导演台：单独的「批量生成」分镜子素材
多选工具栏「生成视频」：只有选中「文本 + 已出图」时，会新建一个视频节点再生成，不是把选中节点各自跑一遍
Agent 侧也刻意不做「一键跑整张图」——那是 Agent 自动开火；这次要的是用户框选后自己点一下。

要先钉死的是：框选后点「批量生成」，任务怎么跑？

A. 各自独立开跑
每个可生成节点用自己的 prompt / 模型 / 引用立刻提交。选中 5 张图就开 5 个任务，互不等待。适合「同一批变体一起出」。

B. 沿选中子图按边串行
先上游、后下游；上游没成功，下游不开。适合「图 → 视频 → 配音」这种流水线，一次框选当一次工作流。

C. 混合（推荐候选）
选中范围内：没连边的并行；有连边的按拓扑等上游。用户不用事先想清楚图结构。

已完成 / 不可生成节点，批量生成时怎么处理？

A. 只补跑缺口（推荐）
可生成且还没可用结果的节点才进队列（草稿、失败、空 URL）。已出图/出视频的当「已完成」跳过，但仍可作为下游引用。组、纯输入、没 prompt 的节点静默排除，工具栏显示「将生成 N / 已选 M」。适合「框一条链，把没出的跑完」。

B. 选中即可重生
所有可生成节点一律重新提交，覆盖旧结果。适合「整批重做」。已完成的也会再扣积分。

C. 默认补跑，可一键强制重生
默认 A；工具栏主按钮是「生成」，旁边或长按「全部重新生成」。多一个入口，但两种意图都覆盖。

建议先做 A（只补跑缺口），不要把 B/C 当 V1 主路径。

框选很粗，几乎总会带上已出图的节点。如果主按钮等于「全部重生」，视频积分会在一次误点里烧掉，这和「把这条链跑完」的心理模型也不一致。混合调度本身就把「已有结果」当成可被下游引用的上游，A 和调度是同一套语义。

B 是高成本误操作。C 的「全部重新生成」有真实需求，但应藏在菜单里，等空队列（选中的都能生成、却全都已有结果）时再露出，而不是两个主按钮抢注意力。

下面这些我会作为架构默认钉死，不需要再逐条投票。若有一条不同意，直接标出来即可。

会进队列的节点
image / video / audio / prompt / text / shot。组、纯输入、导演台、视频合成导出节点不进队列（导演台继续走自己的批量生成）。已在生成中的不打断。pending_confirm 在选区里视为用户已确认，直接开跑。

调度
选区内：无边并行，有边按拓扑等上游。选区外已有结果的上游可以直接引用，不必把整条链都框进来。选区外上游缺失或失败 → 该下游跳过并写明原因，其它独立分支继续。某一节点失败不取消整批。

积分与并发
先估算本批缺口节点费用，不够则整批不启动（与导演台一致）。并行上限 3，单次最多 24 个生成项（与现有构图 dump 同阶）。

入口与取消
多选工具栏主按钮：生成 · N。现有「生成视频」（文本+图 → 新建视频节点）保留，不合并。节点卡片取消仍管单个；工具栏提供「停止全部」。

和现网的关键边界
这是用户框选后的显式操作，不是 Agent「一键跑整张图」（2E-D5 仍然成立）。实现上必须绕开 compositionGenerateIdsForClick：那个函数会把构图组整组展开，会生成选区外的节点。

还差一个我会单独确认的产品点：选区外的上游，是否允许直接当引用？ 我建议允许（上面已按这个写）。如果你要求「没框进来的上游一律不跑、也不引用」，调度和跳过文案会完全不同。

推荐 方案 1：前端编排 + 复用现有 generateForNode。不要为这次做新的服务端批量生成 API。

三条实现路径
方案 1（推荐）— 选区规划器 + 波次执行器
纯函数算出「谁跑、谁跳过、谁等谁」，执行层只调用已经跑通的单节点生成（轮询、取消、扣积分、错误徽章都不用重做）。构图组已经证明这条路：asRunGroupMember: true 可以关掉「点一下展开整组」的副作用。

优点：改动面小，异构节点（图/视频/文/音频）都能走现网 studio；Agent 的 2E-D5（禁止一键跑整张图）不受影响，因为入口是用户框选。
代价：批次协调器在内存里。刷新后节点轮询仍能收口结果；「停止全部」只对当前页有效。这够 V1。
方案 2 — 新 POST /studio/selection-batch
服务端拓扑 + 预扣积分 + 执行。导演台批量就是这个模式，但它只服务同构分镜。选区是图/视频/文/音频混跑，等于把 generateForNode 整段搬到 Nest，还要处理 pending_confirm、fallback 弹窗、引用解析。积分预扣好看，工程成本和分叉风险都高。

方案 3 — 把批次写进 canvasData 做可恢复任务
刷新可续跑。V1 用不上：生成记录已经挂在节点上，刷新后单节点轮询会接手。
