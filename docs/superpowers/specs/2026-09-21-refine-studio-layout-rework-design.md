## 1. 目标

把「进入精修后的页面」从当前的**控件堆叠**重组成**职责清晰的三块**，并让画布在精修模式下只保留与这张图有关的东西。

要解决的 8 个用户原话问题里，本包覆盖其中 6 个（另 2 个见 §2.2）：

| # | 用户原话 | 本包处置 |
|---|---|---|
| 2 | 单击后菜单太小、透明卡片没辨识度 | 选中条已在 M1 图标化；本包不动 |
| 3 | 宫格切分 UI 丑、看不清格子、2 个发亮格子 | M1 已改 7×7 选择器；本包不动 |
| 4 | 宫格切分没有图标 | M1 已补；本包不动 |
| 5 | 没看到抠图、裁剪按钮 | 见 §2.2（能力包） |
| 6 | hover 预览按钮该去掉/放进单击菜单 | M1 已收敛 6→3；本包不动 |
| 7 | 放大该改「扩图」、文字单独紫色很奇怪 | 见 §2.2（能力包） |
| 8 | 编辑右栏布局凌乱，需要分区 | **本包核心** |

## 2. 范围

### 2.1 本包做（纯 `apps/web`，可独立验收上线）

1. **右栏三段式重组**：顶部固定对照预览 / 中部工具箱（唯一滚动区）/ 底部 dock。
2. **画布接管操作与视图**：新增画布左缘竖排工具条（输入组 3 项 + 查看组 2 项），右栏原有三排图标工具条整组下线。
3. **精修模式下画布 chrome 让位**：左上「画布名」区、右上「导入/导出/主题」、左 dock 整条隐藏；原位补一枚「← 返回画布」。
4. **右栏对照区精简**：删模式按钮（左右/滑竿）与放大镜及其子控件；只留「去全屏」一枚动作；预览提到滚动区之外做成固定带。
5. **dock 与图片节点 dock 同构**：header / 参考附件条 / 提示词区 / 底排动作。
6. **顶部模式条**：承担「当前模式 + 当前工具参数 + Esc」，工具参数从右栏迁到这里。

### 2.2 本包不做（各自独立成包）

| 项 | 原因 | 归属 |
|---|---|---|
| **扩图（outpainting）** | 新增能力，需引擎（`@lnkpi/image-editor`）+ 后端通道 + 积分定价 | 下一包，需先出能力设计 |
| **「放大 2X」整条下线** | 触碰 `SelectionActionBar` 与积分文案，非布局问题 | 随扩图包一起做（两件事同一决策链） |
| **抠图 / 裁剪按钮** | M2 能力，spec 已定义（`@lnkpi/image-editor` 引擎包 + 裁剪 + 一键抠图） | M2 包 |
| **批量确认卡 / 自动模式** | 无关 | PR-A/PR-B（已有计划） |

> 用户已明确选择「只做布局重组」；`docs/superpowers/specs/2026-09-21-image-editor-unified-design.md` 的 M2 排期不受本包影响。

## 3. 目标架构

### 3.1 整屏三块

```
┌───────────────────────────────────────────────────────────────┬──────────────────┐
│ 画布区（精修视口，z-40，right: insetRight）                     │ 右栏 .refine-side │
│                                                               │  fixed z-55       │
│  ┌──────┬──────────────────────────────────────────────┐       │  width 400px      │
│  │      │  模式条（当前模式 + 工具参数 + Esc）           │       │ ┌──────────────┐  │
│  │ 左栏 ├──────────────────────────────────────────────┤       │ │ head   46px  │  │
│  │ 工具 │                                              │       │ ├──────────────┤  │
│  │ 条   │        工作图（画布 = 主操作面）               │       │ │ 对照预览 固定 │  │
│  │ 56px │        滚轮缩放 · 空格拖动平移                  │       │ ├──────────────┤  │
│  │      │                                              │       │ │ 工具箱       │  │
│  │ 竖排 │                                              │       │ │ 唯一滚动区   │  │
│  │ 居中 │                                              │       │ ├──────────────┤  │
│  └──────┴──────────────────────────────────────────────┘       │ │ dock  常驻    │  │
│  ← 返回画布（left-3 top-3, z-50，chrome 层）                    │ └──────────────┘  │
└───────────────────────────────────────────────────────────────┴──────────────────┘
```

**布局实现方式**：左栏工具条与模式条**放进 `RefineWorkViewport.vue` 内部**（不新增浮层、不新增 z-index 争用），`.refine-work` 由「单个 stage」改为**横向 flex**：

```
.refine-work (absolute inset:0 z-40; right: insetRight; flex-row)
├── .refine-work__rail   ← RefineToolRail.vue      固定 56px 宽，内容垂直居中
└── .refine-work__col    ← flex:1 flex-column min-width:0
    ├── RefineModeBar.vue                           自动高（≈32px）
    └── .refine-work__stage                         flex:1（现有 stage，逻辑不变）
```

「← 返回画布」留在 `CanvasPage.vue` 的 chrome 层（`left-3 top-3 z-50`），因为它是画布级控件；工具条内容垂直居中，顶部留白正好容纳它，两者不重叠。

### 3.2 两层工具模型（已拍板的判定规则）

> **判据：产出物是「中间态」还是「最终产物」。** 中间态（选区 / 蒙版 / 视图）→ 画布工具条；最终产物（一张新图）→ 工具箱。

本包只落地画布侧（工具箱内的产出型工具属 M2+，见 §2.2），工具箱先承载现有内容（快速预设 + 版本历史）。

## 5. 派生实现约定（P1，由 P0 推导，可否决）

P0 只说了「要有 3 个输入工具」，但现有 6 个工具能力（`brush / eraser / rect / wand / polygon / point`）必须都留活口。以下为**推导出的实现细则**，一并钉死；若要改，请在开工前说。

| # | 约定 | 理由 |
|---|---|---|
| P1-1 | **3 个输入工具各带二级菜单**，容纳 6 个既有能力：<br>`智能选择 ▸ 点选主体(point) / 魔棒(wand)`<br>`框选 ▸ 矩形(rect) / 多边形(polygon)`<br>`涂抹 ▸ 画笔(brush) / 橡皮(eraser)` | 「魔术棒并入智能选择」已在两层工具模型阶段拍板；子菜单是唯一不丢能力的落地方式 |
| P1-2 | **两个选区命令进子菜单**：`智能选择 ▸` 尾部加 `反选`；`涂抹 ▸` 尾部加 `清除选区` | 它们是对选区的即时动作，不属于任何参数面板 |
| P1-3 | **「适配」同样带二级菜单**：`适应窗口(resetView)` / `原始比例 1:1(zoomOneToOne)` | 现有视口 header 有 `1:1` 按钮；不因重组把已上线能力弄丢 |
| P1-4 | **模式条参数矩阵**（由 `RefineMaskTool` 决定显示什么）：<br>`brush` / `eraser` → 粗细滑杆 + 颜色<br>`wand` → 容差滑杆<br>`polygon` → 「单击落点 · 双击闭合」文字提示<br>`rect` / `point` → 无参数 | 左栏是 56px 窄条，放不下滑杆 |
| P1-5 | **对照模式条文案**：`对照 · 左右对照` / `对照 · 滑竿对照`，右端 `Esc 回到工作图` | 与 P0-4 的菜单选项同名 |
| P1-6 | **Esc 分级**：对照模式中 → 退出对照回工作图；工作图 → 退出精修（现状） | 复用 `RefineWorkbench.onClose` 已有的 `compareLightboxOpen` 分支 |
| P1-7 | **`compareMode` / `wipeRatio` 提升到 store**（`canvasEditor`），因为左栏与右栏都要读它 | 现在它们是 `RefineSidePanel` 的局部 ref，两个消费者会打架 |
| P1-8 | **工具箱两组**：`快速预设`（清除瑕疵 / 编辑意图）｜ `版本历史`（`VersionStrip`）。不预置空的能力组标题 | 布局包不造假 UI；M2 工具到位时再加组 |
| P1-9 | **dock 的「模型参数 / 尺寸 / 附件」改为只读状态位**，不做可点控件 | 见 §6 硬约束 —— 精修通道暂不接受这些参数，做活控件会是死控件 |
| P1-10 | **右栏无模式按钮后，选对照方式的唯一入口 = 左栏「对照」**；右栏 `⛶` 沿用当前 `compareMode` 全屏 | 与 P0-6 一致 |

## 6. 硬约束与已查明的事实（实现时必须遵守）

### 6.1 精修通道不接受模型/尺寸/参考图 —— 所以 dock 那三项做只读

已核实（`apps/server/src/studio/studio.controller.ts:382-403`、`studio.service.ts:1310-1320`）：

```
POST /studio/image/edit  body = { prompt, imageUrl, maskUrl, sessionId?, nodeId?, parentRecordId?, parentVersionId? }
```

- **没有** model 字段（服务端写死 `P1_IMAGE_EDIT_MODEL_KEY`）
- **没有** 尺寸 / 分辨率 / 张数字段
- **没有** 参考图数组字段（`capabilities.maxRefImages` 只喂给 guide picker 的可用性判断）

因此 P1-9：dock 里 `模型` `尺寸` 以**只读 chip** 呈现（模型 = 该通道实际使用的模型；尺寸 = 原图 `宽×高 · 比例`），参考条以**只读 chip** 呈现原图（`[I1][原图][缩略图]`），**不渲染 `+` 上传按钮**。
→ 想要可用的模型/尺寸/附件，需要独立的「精修通道参数化」包（后端 DTO + provider 透传 + 积分），不在本包。

### 6.2 `.bottom-toolbar-container` 有 600px 最小宽 —— 塞进 400px 右栏会横向溢出

`apps/web/src/styles/neo-node.css:1051`：

```css
.bottom-toolbar-container { min-width: min(600px, calc(100vw - 32px)); }
```

`RefineDock` 复用 `DockToolbarShell` 时必须覆写：

```css
/* RefineDock.vue <style scoped> —— 精修右栏是 400px 竖版，必须解除底栏的 600px 最小宽 */
.refine-dock :deep(.bottom-toolbar-container) {
  min-width: 0;
  width: 100%;
}
/* ::before 的 topline 内缩 24px、::after 的 -32px/-40px 出血是为横版底栏设计的 */
.refine-dock :deep(.bottom-toolbar-container)::after { display: none; }
```

### 6.3 画布左 dock 现在真的压在精修工作室上（既有缺陷）

层级实测：`.refine-work` = `absolute inset-0 z-40`；`.node-panel-dock` = `absolute left-3 top-[60px] z-[50]`；右上工具条同 `z-[50]`。**50 > 40，两者当前都浮在精修视口之上**，右上工具条还会和精修右栏顶角打架。这是 P0-10/11/12 要修的对象，不是新需求。

### 6.4 「左侧菜单」的命名陷阱（实现时别改错地方）

| 叫法 | 组件 | 位置 | 本包处置 |
|---|---|---|---|
| **画布左 dock**（用户口中的「左侧菜单」） | `NodePanelDock.vue`（`CanvasPage.vue:4083` 挂载） | 画布**左上角** `left-3 top-[60px]`，竖向胶囊：添加 / 资产库 / 任务 / 设置 / 常驻 | **整条隐藏** |
| **精修工具条**（本包新建） | `RefineToolRail.vue` | 画布**左缘垂直居中**，56px 宽 | 新建（精修模式唯一保留） |

两者都在画布左侧但完全不同，混了就会改错。

### 6.5 窄屏（`< 640px`）现状：收起按钮被移除

`RefineSidePanel.vue:415` 的 `v-if="!isNarrow"` + `useWorkbenchPanel.syncNarrow()` 强制 `collapsed = false` + 面板 `width: 100%`。
本包**不新增**窄屏行为（不在范围内）；但左栏工具条与模式条在窄屏下必须仍然可用（右栏此时全屏占位，精修视口 `insetRight = 0`，工具条叠在右栏下面 —— 已知、可接受、记入 §9 风险）。

## 8. 高度账（770px 视口，右栏 400px 宽）

| 区块 | 高度 | 说明 |
|---|---|---|
| 右栏 head | 46px | 收起钮 + 类型图标 + 「精修」 + ✕（现状保留） |
| **对照预览（固定带）** | **≈146px** | 标题行 24 + gap 7 + 双图 96 + 上下内边距 19 |
| dock（常驻） | ≈235–340px | header 24 + 参考条 32 + 提示词 96–200 + 底排 37 + 内边距/gap ≈22 |
| **工具箱滚动区（余量）** | **≈238–343px** | 770 − 46 − 146 − (235~340)；四组内容约 320px → **最长那档要滚一点** |
| 同上 · 提示词收窄到最小时 | ≈343px 上限 | dock 取 235px 时 |

**已拍板的取舍**：对照预览**常在且固定**（P0-7）必然占掉 ≈146px，工具箱因此轻微滚动 —— **接受**。dock 取**常驻**（不做默认折叠），不引入折叠态这个额外状态。
